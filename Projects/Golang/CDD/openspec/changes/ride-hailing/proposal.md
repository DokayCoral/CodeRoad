## Why

构建网约车平台的核心功能——打车（乘客发起叫车请求、系统匹配司机、完成行程）。这是整个平台的基础业务流程，后续所有功能（拼车、预约、企业用车等）都将依赖此核心链路。现在从零开始，首先搭建这条最关键的端到端流程。

## What Changes

- 新增乘客叫车接口：提交起终点位置，创建叫车请求
- 新增司机匹配逻辑：根据司机位置和状态分配最近的可用司机
- 新增行程生命周期管理：请求 → 等待接单 → 已接单 → 司机到达 → 行程中 → 已完成/已取消
- 新增计费规则：基于里程和时长的阶梯计价模型
- 新增订单状态追踪：乘客和司机双端实时查询订单状态

## Capabilities

### New Capabilities

- `ride-request`: 乘客发起叫车请求，包含起终点位置信息，生成待匹配的行程订单
- `ride-matching`: 系统根据司机实时位置和可用状态，为待分配订单匹配最优司机
- `ride-lifecycle`: 管理行程从创建到完成/取消的完整状态流转
- `ride-pricing`: 基于行驶距离、时长、时段等因素计算行程费用

## Impact

- 新增业务代码目录：`src/` 下创建 `ride/` 模块，包含请求、匹配、生命周期、计费等子模块
- 新增测试框架代码目录：`test/` 下创建模拟乘客/司机行为、监控系统状态、测试运行指标的测试工具
- 新增数据表：订单表、行程记录表、计费规则表
- 新增 API 接口：乘客端叫车、查询订单；司机端接单、行程操作
- 依赖技术：Gin（HTTP路由）、GORM（ORM）、MySQL（持久化）、Redis（位置缓存/司机状态）、RPC（服务间调用）
